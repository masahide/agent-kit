# doc-desk Mod 利用者ガイド

## 概要

doc-desk は、Claude が文書 (設計書、仕様書、企画書、記事) を書く前に、人に決めてほしいことだけをブラウザのフォームで聞くための Mod です。Mod は、Claude Code の試験機能「Claude Mods」の仕組みで作った plugin です。Claude Mods は、Claude Code の動きを TypeScript で書いたフック関数で拡張する仕組みで、2026-09 時点では公式ドキュメントに載っていない早期アクセスの機能です。

フォームには、Claude がこれから書く文書の構成案と、人に決めてほしい論点 2〜5 問が出ます。人は選択肢を選んで [送信] を押すだけです。回答は Claude に届き、Claude はそれを反映して文書を書きます。

この Mod を使うと宣言したセッションでは、Claude は書き上げた文書もブラウザに出します。この画面を「指摘の画面」と呼びます。人が段落や文字列に指摘を付けたり、段落をその場で書き換えたりして送信すると、Claude は文書を直してから報告します。

使うには、Claude Mods を有効にし、このリポジトリの `plugins/doc-desk` を読み込みます。CLI と Desktop アプリのどちらでも使えます。Mod の内部構造は [plugins/doc-desk/README.md](../../plugins/doc-desk/README.md) にあります。このガイドは使う側の手順だけを扱います。

## 1. 使う流れ

利用者から見える流れは次の 6 段です。

1. 人が Claude に文書を頼む (例: 「docs/api.md に認証の仕様書を書きたい」)。
2. Claude はリポジトリの資料やコードを調べ、これから書く文書の構成案 (見出しと各節の要旨) を作る。事実で決まることは Claude が自分で決め、好みや優先度で決まる論点だけを 2〜5 問に絞る。問いは、構成案の中でその決定によって文が変わる箇所に、番号付きの印で置く。構成案と問い、根拠、選択肢、推奨案をまとめたものを「質問票」と呼ぶ。
3. Claude は、文脈を持たないサブエージェントに質問票を試し読みさせ、伝わらない問いを直す。このため、フォームが出るまで数分かかることがある。
4. ブラウザにフォームが開く。人が答えて [送信] を押す。
5. Claude が回答を読み、文書を書く。
6. 宣言したセッションでは、ブラウザに指摘の画面が開く。人が段落や文字列に指摘を付けて [送信] を押すと、Claude は文書を直し、指摘ごとに直した箇所か直さなかった理由を報告する。直すところが無ければ、何も付けずに [送信] を押す。

問いを 5 問までに絞る理由や、試し読みの検査項目は [SKILL.md](../../plugins/doc-desk/skills/doc-desk/SKILL.md) にあります。

## 2. 使う前に用意するもの

| もの | 条件 |
|---|---|
| Claude Code | 2.1.278 で動作を確認した。Claude Mods は試験機能なので、版が変わると動かなくなることがある |
| Python 3 | フォームの回答を受け取るサーバ (受信サーバ) に使う。標準ライブラリだけで動く。`python3`、`python`、`py -3` のどれかで `--version` が Python 3 と答えれば足りる (Mod はこの順に探す) |
| OS | macOS、Linux、Windows で動く。ブラウザは、macOS では `open`、Linux では `xdg-open`、Windows では既定のブラウザ (ファイルの関連付け) で開く |
| このリポジトリ | 手元に clone しておく。Mod は配布の仕組み (marketplace) にまだ載っていないので、フォルダを直接読み込む |

## 3. Mod を読み込む

### 3.1 有効化の考え方

Claude Mods を動かすには、次の 2 つを Claude Code に伝えます。

- `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`: Claude Mods の機能そのものを有効にする環境変数。これが無いと、Mod を読み込んでもフックが動かない。
- Mod のフォルダの場所: どのフォルダを plugin として読み込むか。CLI では起動オプション `--plugin-dir`、Desktop アプリでは環境変数 `CLAUDE_CODE_PLUGIN_DIRS` で渡す。

どちらも、その起動 (セッション) の間だけ効きます。Claude Code の設定を恒久的に書き換えるものではありません (Desktop アプリで `~/.claude/settings.json` に書いた場合を除きます)。

### 3.2 CLI で使う

リポジトリの直下で次を実行します。

```bash
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir plugins/doc-desk
```

別のリポジトリで文書を書くときは、`--plugin-dir` に Mod のフォルダの絶対パスを渡し、そのリポジトリの直下で起動します。

```bash
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir /path/to/agent-kit/plugins/doc-desk
```

Mod は、質問票や回答の記録 (証跡ファイル、6 章) を、起動したディレクトリの直下の `doc-desk/` に書きます。

### 3.3 Desktop アプリで使う

Desktop アプリには起動オプションを渡せないので、`~/.claude/settings.json` の `env` に 2 つの環境変数を書きます。プロジェクトの `.claude/settings.json` に書いても読まれません。

```json
{
  "env": {
    "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1",
    "CLAUDE_CODE_PLUGIN_DIRS": "/path/to/agent-kit/plugins/doc-desk"
  }
}
```

書いたあと、Desktop アプリを再起動してから新しいセッションを開きます。

Desktop アプリでは、CLI と次の点が違います (2026-09-23 確認)。

- **ペインが出ない。** ペインは、Mod が CLI の画面の中に開く小さな表示枠で、回答を待つ間、フォームの URL と経過秒数を出す (4.3 節)。Desktop アプリで出ない原因はまだ分かっていない。フォームはブラウザで自動的に開くので、答えるのに支障はない。
- **回答を待っている間に Claude の処理を止めると、Claude には「ツールの実行が拒否された」と見える。** それでもフォームは生きている。あとで [送信] を押すと、回答は新しいメッセージとして Claude に届く。

この設定は、Desktop アプリの全セッションに効きます。使わないときは `env` の 2 行を消して再起動します。

### 3.4 読み込めたかを確かめる

セッションで `/doc-desk-resume` を実行します。「待機中の質問票も指摘の画面もありません」と返れば、Mod は読み込まれています。コマンドが見つからないときは、環境変数とフォルダの場所を見直します。

## 4. 使い方

### 4.1 頼み方

ふだんどおり文書を頼みます。「仕様書を書いて」「設計書を作りたい」「この文書を更新して」「書く前に確認して」などの言い方で、Claude はこの Mod の手順に入ります。

確実に使わせたいときは、スキル名を付けて頼みます。

```
/doc-desk:doc-desk docs/api.md に認証の仕様書を書きたい
```

スラッシュコマンドで頼むか、「この Mod でやろう」のように文で頼むと、この Mod を使うと宣言したことになります。宣言したセッションでは、文書を書き終えるたびに指摘の画面が出ます (4.5 節)。この Mod について尋ねただけでは宣言になりません。指摘の画面を出してほしくなくなったら、「指摘の画面はもう出さないで」のように伝えます。宣言していないセッションでも、「指摘の画面で見せて」と頼めば出ます。

### 4.2 フォームの使い方

フォームは 3 つの領域に分かれています。

| 領域 | 場所 | 中身 |
|---|---|---|
| 構成案 | 左 (画面の大半) | 上から、タイトル、結論 (Claude がいま考えている方針)、このシートで使う言葉、構成案。まだ決まっていないこと (未確定事項) には番号付きの印が付く。表で埋めてほしい情報があれば、構成案の中に入力欄付きの表が入る |
| 詳細 | 右 | 左で選んだものに応じて中身が変わる (下の表) |
| 進捗と送信 | 下 | 未確定事項の数を状態ごとに数えた表示と、[送信] ボタン |

右の詳細の中身は次のとおりです。

| 左で選んだもの | 右に出るもの |
|---|---|
| 何も選んでいない (左の余白を押したとき、右上の [全体] を押したときも同じ) | 全体の進み具合、次に見る項目 ([開く] で開く)、全体へのコメントの欄 |
| 未確定事項の印 | 問い、根拠 (Claude が調べたファイルと行、または実行結果)、選択肢 (利点、代償、選んだときに構成案に入る文)、AI の推奨とその理由、補足の欄、[次の未確認へ] |
| 表の入力欄 | 表の題、空欄の数、[次の未確認へ] |

次に見る項目は、推奨案の無い未確認の問い、推奨案のある未確認の問い、空欄のある表の順に選ばれます。同じ順位の中では構成案の上から選ばれます。

未確定事項の印は、状態に応じて色と文が変わります。

| 状態 | 色 | 印に出る文 |
|---|---|---|
| 未確認 | 黄の番号 | AI の推奨の文 (灰色の破線)。推奨案の無い問いは、選択肢を ` / ` でつないだもの (黄の破線)。送信すると AI の推奨で進む |
| 確認済み | 緑の番号 | 選んだ案の文。推奨案を選んだとき、または推奨案の無い問いで選択肢を選んだときの状態 |
| 推奨から変更 | 赤の番号 | 選んだ案の文。推奨案とは違う選択肢を選んだときの状態 |

画面の幅が 900px より狭いときは、詳細は下から出る領域になります。印を押すか、下の [全体] で開き、[閉じる] で閉じます。

答えるときの決まりは次のとおりです。

- 選ばなかった問いは「お任せ」になり、Claude が推奨案で確定する。全部の問いに答える必要はない。
- 選んだ選択肢をもう一度押すか、選択肢の下の「選択を外す」を押すと、選択を外せる。
- 選択肢に条件を付けたいとき、どちらの案でもないときは、詳細の補足欄に 1 行で書く。Claude は補足を選択肢より優先して読む。
- 構成案そのものに意見があるとき (節が足りない、順番が違うなど) は、全体へのコメントに書く。
- 問いそのものが的外れなら、全体へのコメントにそう書く。Claude は文書を書かずに、質問票を作り直して 2 枚目を出す。
- 書きかけの内容はブラウザに自動で保存される。同じ URL で開き直すと元に戻る (`/doc-desk-resume` で開き直したときも同じ)。`doc-desk/<名前>.html` を直接開いたときは戻らない。

[送信] を押して「送信しました。Claude Code に戻ってください。」と出れば完了です。

### 4.3 回答が Claude に届くまで

届き方は、答えるまでにかかった時間で変わります。Claude はフォームを出すたびに、その場で回答を待つ時間を決めます。ふつうは 5 分で、長くても 30 分です。

| 状況 | 何が起きるか |
|---|---|
| Claude が待っている間に [送信] した | Claude はその場で回答を受け取り、そのまま文書を書き始める |
| Claude が待つのをやめた後に [送信] した (待つ時間を過ぎた、または途中で Claude の処理を止めた) | Claude はいったん応答を終える。あとで [送信] を押すと、回答は `【doc-desk 回答】` で始まるメッセージとして Claude に届き、Claude はそこから文書を書く |
| [取り消す] を押した (CLI のペイン) | 質問票は取り消される。Claude が待っている間に押したときは、Claude は取り消されたことを知り、次の指示を待つ。Claude が待つのをやめた後に押したときは、Claude には何も届かない。どちらの場合も、人が次の指示を出す |

待っている間、CLI ではペインに URL と経過秒数が出ます。ペインの [ブラウザで開く] でフォームを開き直せます。Claude が応答を終えるときは、応答の下に「回答先: <URL>」が 1 行出ます (Desktop ではペインが出ないので、これと通知が手がかりになります)。

回答が届くと、プロンプトの下に「回答を受け取りました: <名前>」と数秒出ます。Claude が応答を終えた後に届いた回答は、会話の中では `【doc-desk 回答】spec-auth-01  Q1=A  Q2=お任せ  補足 1 件` のように 1 行に畳んで出ます。全文は ctrl+o で見られます。Claude には全文が届いています。

回答を待っている間に Claude Code を閉じても、質問票は無駄になりません。次に同じフォルダで Claude Code を起動したとき、Mod は前回の質問票を引き継ぎます。

| 閉じている間に | 次の起動で何が起きるか |
|---|---|
| [送信] した | 「質問票 <名前> の回答が届いています」と出て、プロンプト欄に `/doc-desk-resume` が薄く出る。Tab と Enter で `/doc-desk-resume` を実行すると、回答が Claude に届く。起動しただけでは Claude は動き出さない |
| まだ答えていない | プロンプトの下に「前回の質問票 <名前> が未回答です」と出る。フォームは開いたままのタブで答えてよい。タブを閉じていたら `/doc-desk-resume` で開き直す |

受信サーバが止まっていたときは、Mod が同じ URL で起動し直すので、開いたままのタブと書きかけの内容はそのまま使えます。同じ URL が使えなかったときは、新しい URL を 1 行で知らせます。7 日より前の質問票は引き継ぎません。同じフォルダで別の Claude Code がまだ動いていて、その質問票の回答を待っているときも、引き継ぎません (回答はその Claude Code に届きます)。

`claude -p` のように人がいない使い方では、届いていた回答を起動時にそのまま Claude に渡します。

回答を待っている間は、Claude がフォームで決めることを先回りして文書を書かないよう、Mod が止めます。Claude が質問票に書いた「これから書く文書」(指摘の画面では元の文書) への書き込みは、回答が Claude に届くまで拒まれます。回答が届いていて `/doc-desk-resume` で送る前の間も同じです。ほかのファイルへの書き込みは止めないので、待つ間に別の作業を頼めます。Claude が Bash などで直接書く場合は止められません。

会話が長くなって圧縮 (`/compact` や自動の圧縮) されても、フォームや指摘の画面で答えた内容は要約で薄まりません。Mod が、このセッションで届いた回答の全文を「【doc-desk 決定の記録】」として要約の後ろに残します。

### 4.4 ブラウザを閉じてしまったら

`/doc-desk-resume` を実行すると、フォームをブラウザで開き直します (CLI ではペインも開き直します)。回答を待っている間なら、いつでも使えます。Claude Code を閉じて起動し直した後でも使えます (4.3 節)。書きかけの内容は 4.2 節のとおり復元されます。

### 4.5 指摘の画面の使い方

指摘の画面は、フォームと同じく左と右に分かれています。

| 領域 | 場所 | 中身 |
|---|---|---|
| 文書 | 左 | 書き上げた文書。見出し、段落、箇条書き、表の行を押せる |
| 指摘 | 右 | ふだんは指摘の一覧と全体へのコメント欄。段落を押すと、指摘を付ける操作に変わる |
| 送信 | 下 | 指摘の数と [送信] |

画面を開くと、Claude が自分で見つけた直しどころ (最大 5 件) が「Claude の候補」として出ていることがあります。候補のある段落には薄い黄色の帯と「Claude の候補」の印が付き、右の「Claude の候補」の一覧に [採用] と [却下] が並びます。[採用] を押すと候補は指摘の一覧に入り、[却下] を押すと消えます。どちらも押さなかった候補は Claude に送りません。候補を作るために、Claude は画面を出す前に 1 回だけ追加でモデルに問い合わせます。会話の続きとして聞くのでキャッシュが効き、費用は主に候補の出力分ですが、画面が開くまで数秒から数十秒余分にかかります。その間に Claude の処理を止めると、画面は出ません。候補を出したくないときは、Claude に「候補は要らない」と伝えるか、plugin の設定で `selfReview` を切ります。

指摘には、チップ (指摘の種類を表す短い言葉のボタン) とコメントを付けられます。チップは、短くする、言い換える、分かりやすく、具体例を足す、根拠が要る、削る、順序を入れ替える、図を直す、ここは良い、の 9 種です。指摘の付け方は次のとおりです。

1. 左の段落を押す。一部に付けたいときは、段落の中の文字列をマウスで選択する。マウスを離すと、選んだ文字列が黄色で囲まれ、右で指摘を書いている間も残る。
2. チップかコメント (または両方) を入れて [指摘を足す] を押す。
3. 指摘した段落には、左に線と番号が付く (「ここは良い」だけなら緑)。文字列に付けた指摘は、その文字列に青い下線と指摘の番号が残る (「ここは良い」なら緑の下線)。
4. 指摘は一覧の [消す] で消せる。[指摘を足す] で足した指摘と、段落の書き換え、全体へのコメントはブラウザに自動で保存される。入力欄に書きかけで、まだ [指摘を足す] を押していないチップとコメントは保存されない。
5. 全部付けたら [送信] を押す。直すところが無ければ、何も付けずに [送信] を押す。

段落をその場で直すこともできます。段落を押して、右の「直接直す」のボタンを使います。

| ボタン | すること |
|---|---|
| [書き換える] | 段落の書き換え。入力欄で文を直し、使い方 (下の表) を選んで [確定] (Ctrl+Enter) を押す。太字などの印は外れた文で書き、Claude が付け直す |
| [この段落を消す] | 段落の削除。もう一度押すと取り消せる |
| [移動する] | 段落の移動。移動先の段落番号を入れて [確定] (Enter) を押すと、その段落の後へ動かす (下の説明) |
| [この下に段落を足す] | 段落の追加。段落の下に新しい段落を足す。書き換えと同じく使い方を選ぶ |

段落番号は文書の中には書かれていません。段落にマウスを載せると「段落 3」のように出ます。段落を押したときは、右の指摘の領域に「#3」と出ます。[移動する] を押しても、画面の上では段落は動きません。段落に「移動 → #5 の後へ」のような印が付き、Claude が文書を直すときに動かします。移動先は「その段落の後」しか選べないので、段落を文書の先頭へは動かせません。先頭に置きたいときは、元の先頭の段落を目的の段落の後へ動かします。

書き換えた文と足した文には、2 つの使い方があります。

| 使い方 | Claude がすること |
|---|---|
| そのまま使う (既定) | 書いた文を一字一句そのまま文書に入れる |
| 参考にして直す | 書いた文を「こうしたい」という見本として読み、その意図に沿って、前後の文に合う文を書く。完了報告で、書いた文と Claude が書いた文を並べて示す |

直した段落には、左に赤い線と「書き換え」「削除」「移動 → #N の後へ」「追加」の印が付きます。直したものは右の一覧の [元に戻す] で取り消せます。

「ここは良い」を付けた箇所は、Claude は直しません。

長い文書 (タグを含む HTML で 10 万文字を超えるもの) は、Claude が節の切れ目で分け、何回かの画面に分けて出します。画面の上に「1 / 2 回目」のように出ます。

## 5. 困ったとき

| 症状 | 対処 |
|---|---|
| Claude が「doc-desk Mod が読み込まれていません」と言った | 3.4 節で確かめ、3.2 節か 3.3 節の手順で読み込み直す |
| 「Python 3 (python3、python、py -3 のどれか) が見つからないため受信サーバを起動できませんでした」と言われた | Python 3 を入れてから頼み直す。Windows で Python を入れているのにこう言われたときは、`python --version` が通るかを確かめる。すぐ答えたいときは、下の「ブラウザが開かない」と同じ手順で答えられる |
| [送信] すると「受信サーバが応答しません」と出て、JSON が表示された | 表示された JSON をそのまま Claude Code のチャットに貼る。Claude はそれを回答として読む |
| フォームか指摘の画面が開いてから 1 時間を過ぎて [送信] したら、「受信サーバが応答しません」と出た | 受信サーバは、開いてから 1 時間で止まる。表示された JSON をそのまま Claude Code のチャットに貼る。Claude Code を起動し直すと受信サーバも同じ URL で起動し直すので、その後なら [送信] をもう一度押してもよい |
| 起動したら「質問票 <名前> の回答が届いています」と出た | 前回閉じている間に送った回答が届いている。`/doc-desk-resume` を実行すると Claude に届く (4.3 節) |
| Claude が次のフォームか指摘の画面を出した後で、前の画面の [送信] を押したら、「受信サーバが応答しません」と出た | Claude が次の画面を出すと、前の画面の受信は止まる。前の画面の回答が要るなら、表示された JSON をチャットに貼り、どの画面の回答かを添える |
| ブラウザが開かない | `doc-desk/<質問票の名前>.html` を直接ブラウザで開いて答える。この場合 [送信] で JSON が表示されるので、それをチャットに貼る |
| 答えを間違えて送信した | チャットで「問 2 は B に変えて」のように伝える。Claude は文書にそれを反映する |

## 6. 証跡ファイル

Mod は、質問票と指摘の画面ごとに、作業ディレクトリ直下の `doc-desk/` へ次のファイルを残します。これを証跡ファイルと呼びます。`<名前>` は画面ごとに Claude が付ける名前です (例: `spec-auth-01`、指摘の画面なら `spec-auth-01-review`)。

| ファイル | 中身 |
|---|---|
| `<名前>.json` | 質問票 (指摘の画面では、画面の設定) |
| `<名前>.doc.html` | 指摘の画面に出した文書 (Claude が書いたもの) |
| `<名前>.html` | フォーム。ブラウザで直接開ける |
| `<名前>.candidates.json` | 指摘の画面に出した Claude の候補 |
| `<名前>.answer.json` | ブラウザが送った回答 |
| `<名前>.md` | Claude に届けた回答の文面 (`【doc-desk 回答】` で始まる) |

これらは「なぜこの文書がこう決まったか」の記録です。Mod は、同じ名前でフォームか指摘の画面を出し直すときだけ、前回の `<名前>.answer.json` を消し、`<名前>.json` と `<名前>.html` を書き直します。名前の違うファイルは、Mod も Claude も消しません。不要になったら人が消します。このリポジトリでは `.gitignore` で `/doc-desk/` を git の対象から外しています。
