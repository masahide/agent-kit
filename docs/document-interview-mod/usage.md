# Document Interview Mod 利用者ガイド

## 要点

- この Mod は、Claude が文書 (設計書、仕様書、企画書、記事) を書く前に、文書の構成案と、人に決めてほしい論点 2〜5 問をフォームにしてブラウザに出します。
- 人はブラウザで選択肢を選び、[送信] を押すだけです。回答は Claude に届き、Claude はそれを反映して文書を書きます。
- この Mod を使うと宣言したセッションでは、Claude は書き上げた文書もブラウザに出します (指摘の画面)。人が段落や文字列に指摘を付けて送信すると、Claude は直してから報告します。
- 使うには、Claude Code の試験機能「Claude Mods」を有効にし、このリポジトリの `plugins/document-interview` を読み込みます。CLI と Desktop アプリのどちらでも使えます。

Mod の内部構造は [plugins/document-interview/README.md](../../plugins/document-interview/README.md) にあります。このガイドは使う側の手順だけを扱います。

## 1. 用語

| 語 | 意味 |
|---|---|
| Claude Mods | Claude Code の動きを、TypeScript で書いたフック関数で拡張する仕組みです。plugin の一種です。2026-09 時点では公式ドキュメントに載っていない試験機能 (早期アクセス) で、環境変数 `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1` を設定したときだけ動きます。 |
| Mod | Claude Mods の仕組みで作った plugin 1 つを指します。このガイドでは Document Interview Mod (`plugins/document-interview`) のことです。 |
| 質問票 | Claude が論点を整理して作る、フォームの元になるデータです。構成案、問い、根拠、選択肢、推奨案が入っています。 |
| 構成案 | Claude がこれから書く文書の見出しと各節の要旨です。まだ決まっていないこと (未確定事項) の箇所に、番号付きの印が付きます。 |
| お任せ | 人が選択肢を選ばなかった問いの扱いです。Claude は推奨案で確定します。 |
| 宣言 | 人が、そのセッションでこの Mod を使うと示すことです。スラッシュコマンド `/document-interview:document-interview` で頼むか、「この Mod でやろう」のように文で頼むと宣言になります。 |
| 指摘の画面 | 書き上げた文書をブラウザに出し、人が段落や文字列に直してほしいことを付けて返す画面です。宣言したセッションでは、Claude が文書を書き終えるたびに出ます。 |
| チップ | 指摘の種類を表す短い言葉のボタンです (短くする、言い換える、分かりやすく、具体例を足す、根拠が要る、削る、順序を入れ替える、図を直す、ここは良い)。 |
| 証跡ファイル | Mod が質問票ごとに、作業ディレクトリ直下の `interview/` フォルダへ残すファイルです。質問票、フォームの HTML、回答の JSON、Claude に届けた回答の文面があります。 |
| ペイン | Mod が Claude Code の画面の中に開く小さな表示枠です。回答を待つ間、フォームの URL と経過秒数を出します。CLI でだけ表示されます (4.3 節)。 |

## 2. 何が起きるか

利用者から見える流れは次の 6 段です。

1. 人が Claude に文書を頼みます (例: 「docs/api.md に認証の仕様書を書きたい」)。
2. Claude はリポジトリの資料やコードを調べ、これから書く文書の構成案を作ります。事実で決まることは自分で決め、好みや優先度で決まる論点だけを 2〜5 問に絞り、構成案の中の影響する箇所に印で置きます。
3. Claude は、文脈を持たない別の Claude に質問票を試し読みさせ、伝わらない問いを直します。このため、フォームが出るまで数分かかることがあります。
4. ブラウザにフォームが開きます。人が答えて [送信] を押します。
5. Claude が回答を読み、文書を書きます。文書には「決定事項」として、各問の決定とお任せで確定した項目が載ります。
6. 宣言したセッションでは、ブラウザに指摘の画面が開きます。人が段落や文字列に指摘を付けて [送信] を押すと、Claude は文書を直し、指摘ごとに直した箇所か直さなかった理由を報告します。直すところが無ければ、何も付けずに [送信] を押します。

問いを 5 問までに絞る理由や、試し読みの検査項目は [SKILL.md](../../plugins/document-interview/skills/document-interview/SKILL.md) にあります。

## 3. 使う前に用意するもの

| もの | 条件 |
|---|---|
| Claude Code | 2.1.278 で動作を確認しています。Claude Mods は試験機能なので、版が変わると動かなくなることがあります。 |
| Python 3 | フォームの回答を受け取るサーバに使います。標準ライブラリだけで動きます。`python3`、`python`、`py -3` のどれかで `--version` が Python 3 と答えれば足ります (Mod はこの順に探します)。 |
| OS | macOS、Linux、Windows で動きます。ブラウザは、macOS では `open`、Linux では `xdg-open`、Windows では既定のブラウザ (ファイルの関連付け) で開きます。 |
| このリポジトリ | 手元に clone しておきます。Mod は配布の仕組み (marketplace) にまだ載っていないので、フォルダを直接読み込みます。 |

## 4. Mod を読み込む

### 4.1 有効化の考え方

Claude Mods を動かすには、次の 2 つを Claude Code に伝えます。

- `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`: Claude Mods の機能そのものを有効にする環境変数です。これが無いと、Mod を読み込んでもフックが動きません。
- Mod のフォルダの場所: どのフォルダを plugin として読み込むかです。CLI では起動オプション `--plugin-dir`、Desktop アプリでは環境変数 `CLAUDE_CODE_PLUGIN_DIRS` で渡します。

どちらも、その起動 (セッション) の間だけ効きます。Claude Code の設定を恒久的に書き換えるものではありません (Desktop アプリで `~/.claude/settings.json` に書いた場合を除きます)。

### 4.2 CLI で使う

リポジトリの直下で次を実行します。

```bash
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir plugins/document-interview
```

別のリポジトリで文書を書くときは、`--plugin-dir` に Mod のフォルダの絶対パスを渡し、そのリポジトリの直下で起動します。

```bash
CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1 claude --plugin-dir /path/to/agent-kit/plugins/document-interview
```

証跡ファイルは、起動したディレクトリの直下の `interview/` に書かれます。

### 4.3 Desktop アプリで使う

Desktop アプリには起動オプションを渡せないので、`~/.claude/settings.json` の `env` に 2 つの環境変数を書きます。プロジェクトの `.claude/settings.json` に書いても読まれません。

```json
{
  "env": {
    "CLAUDE_CODE_ENABLE_FUNCTION_HOOKS": "1",
    "CLAUDE_CODE_PLUGIN_DIRS": "/path/to/agent-kit/plugins/document-interview"
  }
}
```

書いたあと、Desktop アプリを再起動してから新しいセッションを開きます。

Desktop アプリでは、CLI と次の点が違います (2026-09-23 確認)。

- **ペインが表示されません。** 原因はまだ分かっていません。フォームはブラウザで自動的に開くので、答えるのに支障はありません。
- **回答を待っている間に Claude の処理を止めると、Claude には「ツールの実行が拒否された」と見えます。** それでもフォームは生きています。あとで [送信] を押すと、回答は新しいメッセージとして Claude に届きます。

この設定は、Desktop アプリの全セッションに効きます。使わないときは `env` の 2 行を消して再起動します。

### 4.4 読み込めたかを確かめる

セッションで `/interview` を実行します。「待機中の質問票はありません」と返れば、Mod は読み込まれています。コマンドが見つからないときは、環境変数とフォルダの場所を見直します。

## 5. 使い方

### 5.1 頼み方

ふだんどおり文書を頼みます。「仕様書を書いて」「設計書を作りたい」「この文書を更新して」「書く前に確認して」などの言い方で、Claude はこの Mod の手順に入ります。

確実に使わせたいときは、スキル名を付けて頼みます。

```
/document-interview:document-interview docs/api.md に認証の仕様書を書きたい
```

スラッシュコマンドで頼むか、「この Mod でやろう」のように文で頼むと、そのセッションは宣言したことになり、文書を書き終えるたびに指摘の画面が出ます (5.5 節)。この Mod について尋ねただけでは宣言になりません。指摘の画面を出してほしくなくなったら、「指摘の画面はもう出さないで」のように伝えます。宣言していないセッションでも、「指摘の画面で見せて」と頼めば出ます。

### 5.2 フォームの答え方

フォームは 3 つの領域に分かれています。

| 領域 | 場所 | 中身 |
|---|---|---|
| 構成案 | 左 (画面の大半) | 上から、タイトル、結論 (Claude がいま考えている方針)、このシートで使う言葉、構成案 (Claude がこれから書く文書の見出しと各節の要旨) です。まだ決まっていないこと (未確定事項) には番号付きの印が付いています。表で埋めてほしい情報があれば、構成案の中に入力欄付きの表があります |
| 詳細 | 右 | 左で選んだものに応じて中身が変わります (下の表) |
| 進捗と送信 | 下 | 未確定事項の数を状態ごとに数え、[送信] ボタンを置いています |

右の詳細の中身は次のとおりです。

| 左で選んだもの | 右に出るもの |
|---|---|
| 何も選んでいない (左の余白を押したとき、右上の [全体] を押したときも同じ) | 全体の進み具合、次に見る項目 ([開く] で開きます)、全体へのコメントの欄 |
| 未確定事項の印 | 問い、根拠 (Claude が調べたファイルと行、または実行結果)、選択肢 (利点、代償、選んだときに構成案に入る文)、AI の推奨とその理由、補足の欄、[次の未確認へ] |
| 表の入力欄 | 表の題、空欄の数、[次の未確認へ] |

次に見る項目は、推奨案の無い未確認の問い、推奨案のある未確認の問い、空欄のある表の順に選ばれます。同じ順位の中では構成案の上から選ばれます。

未確定事項の印は、状態に応じて色と文が変わります。

| 状態 | 色 | 印に出る文 |
|---|---|---|
| 未確認 | 黄の番号 | AI の推奨の文 (灰色の破線)。推奨案の無い問いは、選択肢を ` / ` でつないだもの。送信すると AI の推奨で進みます |
| 確認済み | 緑の番号 | 選んだ案の文。推奨案を選んだか、推奨案の無い問いで選択肢を選んだときです |
| 推奨から変更 | 赤の番号 | 選んだ案の文。推奨案とは違う選択肢を選んだときです |

画面の幅が 900px より狭いときは、詳細は下から出る領域になります。印を押すか、下の [全体] で開き、[閉じる] で閉じます。

答えるときの決まりは次のとおりです。

- 選ばなかった問いは「お任せ」になり、Claude が推奨案で確定します。全部の問いに答える必要はありません。
- 選んだ選択肢をもう一度押すか、選択肢の下の「選択を外す」を押すと、選択を外せます。
- 選択肢に条件を付けたいとき、どちらの案でもないときは、詳細の補足欄に 1 行で書きます。Claude は補足を選択肢より優先して読みます。
- 構成案そのものに意見があるとき (節が足りない、順番が違うなど) は、全体へのコメントに書きます。
- 問いそのものが的外れなら、全体へのコメントにそう書きます。Claude は文書を書かずに、質問票を作り直して 2 枚目を出します。
- 書きかけの内容はブラウザに自動で保存されます。フォームを開き直すと元に戻ります。

[送信] を押して「送信しました。Claude Code に戻ってください。」と出れば完了です。

### 5.3 回答が Claude に届くまで

届き方は、答えるまでにかかった時間で変わります。

| 状況 | 何が起きるか |
|---|---|
| フォームが開いてから 5 分以内に [送信] した | Claude はその場で回答を受け取り、そのまま文書を書き始めます。 |
| 5 分を過ぎた、または途中で Claude の処理を止めた | Claude はいったん応答を終えます。あとで [送信] を押すと、回答は `【インタビュー回答】` で始まるメッセージとして Claude に届き、そこから文書を書きます。 |
| [取り消す] を押した (CLI のペイン) | 質問票は取り消されます。Claude には何も届きません。次の指示を出してください。 |

待っている間、CLI ではペインに URL と経過秒数が出ます。ペインの [ブラウザで開く] でフォームを開き直せます。

### 5.4 ブラウザを閉じてしまったら

`/interview` を実行すると、フォームをブラウザで開き直します (CLI ではペインも開き直します)。回答を待っている間なら、いつでも使えます。書きかけの内容は 5.2 節のとおり復元されます。

### 5.5 指摘の画面の使い方

指摘の画面は、フォームと同じく左と右に分かれています。

| 領域 | 場所 | 中身 |
|---|---|---|
| 文書 | 左 | 書き上げた文書です。見出し、段落、箇条書き、表の行を押せます |
| 指摘 | 右 | ふだんは指摘の一覧と全体へのコメント欄です。段落を押すと、指摘を付ける操作に変わります |
| 送信 | 下 | 指摘の数と [送信] |

指摘の付け方は次のとおりです。

1. 左の段落を押します。一部に付けたいときは、段落の中で文字列を選びます。
2. チップかコメント (または両方) を入れて [指摘を足す] を押します。
3. 指摘した段落には、左に線と番号が付きます (「ここは良い」だけなら緑)。
4. 指摘は一覧の [消す] で消せます。書きかけの指摘はブラウザに自動で保存されます。
5. 全部付けたら [送信] を押します。直すところが無ければ、何も付けずに [送信] を押します。

「ここは良い」を付けた箇所は、Claude は直しません。言い換えてほしい文は、コメントに書きます (本文をその場で書き換える機能はまだありません)。

長い文書 (10 万文字を超えるもの) は、Claude が節の切れ目で分け、何回かの画面に分けて出します。画面の上に「1 / 2 回目」のように出ます。

## 6. 困ったとき

| 症状 | 対処 |
|---|---|
| Claude が「Document Interview Mod が読み込まれていません」と言った | 4.4 節で確かめ、4.2 節か 4.3 節の手順で読み込み直します。 |
| 「Python 3 (python3、python、py -3 のどれか) が見つからないため受信サーバを起動できませんでした」と言われた | Python 3 を入れてから頼み直します。Windows で Python を入れているのにこう言われたときは、`python --version` が通るかを確かめます。すぐ答えたいときは、下の「ブラウザが開かない」と同じ手順で答えられます。 |
| [送信] すると「受信サーバが応答しません」と出て、JSON が表示された | 表示された JSON をそのまま Claude Code のチャットに貼ります。Claude はそれを回答として読みます。 |
| ブラウザが開かない | `interview/<質問票の名前>.html` を直接ブラウザで開いて答えます。この場合 [送信] で JSON が表示されるので、それをチャットに貼ります。 |
| 答えを間違えて送信した | チャットで「問 2 は B に変えて」のように伝えます。Claude は文書にそれを反映します。 |

## 7. 証跡ファイル

Mod は、質問票と指摘の画面ごとに `interview/` へ次のファイルを残します。`<名前>` は画面ごとに Claude が付ける名前です (例: `spec-auth-01`、指摘の画面なら `spec-auth-01-review`)。

| ファイル | 中身 |
|---|---|
| `<名前>.json` | 質問票 (指摘の画面では、画面の設定) |
| `<名前>.doc.html` | 指摘の画面に出した文書 (Claude が書いたもの) |
| `<名前>.html` | フォーム。ブラウザで直接開けます |
| `<名前>.answer.json` | ブラウザが送った回答 |
| `<名前>.md` | Claude に届けた回答の文面 (`【インタビュー回答】` で始まる) |
| `<名前>.port.json` | 回答を受け取るサーバの接続先 (内部用) |

これらは「なぜこの文書がこう決まったか」の記録です。Mod も Claude も消しません。不要になったら人が消します。このリポジトリでは `.gitignore` で `/interview/` を git の対象から外しています。
