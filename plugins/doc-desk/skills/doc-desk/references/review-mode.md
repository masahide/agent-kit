# 指摘モード — 書き上げた文書を人に見せ、指摘と書き換えを受けて直す

手順 8 (SKILL.md) で使います。人は指摘の画面で、段落に指摘を付けるほか、段落をその場で書き換え、消し、足し、動かせます (添削)。人がこの Mod を使うと宣言したセッションでは、Claude は文書を書き終えるたびに、完了報告の前に指摘の画面を出します。宣言が無ければ、人が頼んだときだけ出します。設計の経緯は agent-kit の `docs/doc-desk/plan.md` の「指摘モードの設計」にあります。

## 1. 宣言の判定

宣言かどうかは Claude が会話を読んで判定します。Mod は判定しません (Mod のフックは、人がスラッシュコマンドでスキルを呼んだのか、Claude が自分で呼んだのかを区別できないため)。

| 発言 | 扱い |
|---|---|
| 人がスラッシュコマンド `/doc-desk:doc-desk` でスキルを呼んだ | 宣言です |
| 「この Mod でやろう」「doc-desk を使って」のように、この Mod を使うと文で頼んだ | 宣言です |
| 「この Mod はどう動くの?」のように、この Mod について尋ねただけ | 宣言ではありません |
| 宣言の後に「指摘の画面はもう出さないで」のように取り消した | 取り消しです。以後は、頼まれたときだけ出します |

宣言は、人が取り消すまでそのセッションの間続きます。スラッシュコマンドでスキルを呼んだセッションでは、基本的に、文書を書き終えた後、完了報告の前に指摘の画面を出します。

## 2. 文書を HTML に書き出す

書き上げた文書 (Markdown など) を、次の規則の HTML に変換して `doc-desk/<label>.doc.html` に書き出します (`Write` ツール)。元の文書は書き換えません。

- 使える要素: `h2`, `h3`, `h4`, `p`, `ul`, `ol`, `li`, `dl`, `dt`, `dd`, `table`, `caption`, `thead`, `tbody`, `tr`, `th`, `td`, `strong`, `em`, `code`, `pre`, `blockquote`, `br`, `hr`, `span`, `div` (構成案と同じ許可リスト)。
- 使える属性: `th` と `td` の `colspan` と `rowspan` だけ。`class`、`style`、`id`、`href`、`data-*` は使いません。リンクは文字だけ残します (`<a href="x">名前</a>` → `名前 (x)`)。
- 文書の題名は `h1` にせず、`review.title` に書きます。Markdown の `#` の見出しは題名、`##` は `h2`、`###` は `h3`、`####` 以下は `h4` にします。
- 画像は描けません。`[図: <説明> (<パス>)]` の段落にします。
- `<html>`、`<head>`、`<body>` は書かず、本文の断片だけを書きます。`<`、`>`、`&` は `&lt;`、`&gt;`、`&amp;` に直します。
- 文字数は、タグを含めて 10 万文字までです。超えるときは節 (`h2`) の切れ目で分け、`<label>-p1.doc.html`、`<label>-p2.doc.html` のように別の画面にします (4 章)。

画面は、自分の文字を持つ `h2`〜`h4`、`p`、`li`、`dt`、`dd` と、`pre`、表の行 (`tr`) に、上から段落番号を振ります。人の指摘はこの番号で届きます。

## 3. open_review の呼び方

ツール名は `mcp__doc-desk__open_review` です。入力は次の形です。

```json
{
  "review": {
    "schemaVersion": 1,
    "documentId": "spec-auth-01",
    "revision": 1,
    "label": "spec-auth-01-review",
    "title": "認証方式の仕様",
    "source": "docs/spec-auth.md"
  },
  "waitSeconds": 300
}
```

| 欄 | 必須 | 規則 |
|---|---|---|
| `schemaVersion` | 必須 | `1` |
| `documentId` | 必須 | `^[A-Za-z0-9_-]{1,64}$`。質問票と同じ文書なら同じ値にします |
| `revision` | 必須 | 1 以上の整数。同じ文書で指摘の画面を出し直すたびに 1 つ進めます |
| `label` | 必須 | `^[A-Za-z0-9_-]{1,64}$`。画面の名前です。Mod は `doc-desk/<label>.doc.html` を読み、証跡を `doc-desk/<label>.*` に書きます。質問票の `label` とは別の名前にします (例: `spec-auth-01-review`、出し直しは `spec-auth-01-review-r2`) |
| `title` | 必須 | 画面の上に出す文書の題名 |
| `source` | 任意 | 元の文書のパス。画面に出すほか、指摘が届くまで Mod がこのパスへの書き込みを止めます (`doc-desk/<label>.doc.html` も止めます) |
| `part` | 任意 | 分けて出すときの `{ "index": 2, "total": 3 }` (index は 1 から、total は 2〜50) |

`selfReview` (任意、既定 `true`) は、画面を出す前に Mod があなた自身 (`$.model.fork` で今の会話の続きとして) に 1 問だけ聞き、文書の直しどころを最大 5 件、画面に「Claude の候補」として出すかどうかです。人は候補ごとに [採用] か [却下] を押すだけです。候補は `doc-desk/<label>.candidates.json` にも残ります。人が「候補は要らない」と言ったときは `false` にします。plugin の設定 `selfReview` が切ってあれば、`true` でも出ません。候補づくりに失敗しても画面はふつうに出ます。

`waitSeconds` と `openBrowser` は `open_form` と同じです。結果の `status` (`answered` / `pending` / `cancelled` / `invalid` / `failed`) も `open_form` と同じ意味です。違いは次のとおりです。

- `files` は `{ doc, review, html }` (`answered` では `answer` と `md` を足す) です。`review` は検証済みの入力 (`doc-desk/<label>.json`) です。
- `invalid` の `errors` には、`review` の欄の誤りに加えて、HTML ファイルの誤り (`<パス>: <直し方>`) が入ります。ファイルが無い、許可リストに無い要素や属性がある、10 万文字を超える、段落が無い、のどれかです。直して同じツールをもう一度呼びます。
- `pending` のとき、指摘は後で `【doc-desk 回答】<documentId>` で始まる user turn として届きます。届くまで文書を直さず、完了報告もせず、ターンを終えます。

## 4. 長い文書

1 回の指摘の画面に出すのは 10 万文字 (タグを含む HTML の文字数) までです。長い文書は、Claude が節の切れ目で区切り、何回かの画面に分けて出します。

1. 文書を `h2` の切れ目で、それぞれ 10 万文字以下になるように分けます。
2. 1 つ目を `part: { index: 1, total: n }` で出し、指摘を受け取って反映します。
3. 次を `revision` を進め、`label` を変えて (`<label>-p2` など) 出します。最後まで繰り返します。
4. 段落番号は画面ごとに 1 から振られます。回答の `対象:` の行で、どの画面の指摘かを確かめます。

## 5. 指摘の回答

人が [送信] を押すと、次の形で届きます (`answered` の `reply`、または user turn)。

```
【doc-desk 回答】spec-auth-01
対象: doc-desk/spec-auth-01-review.doc.html
## 指摘
#1 [ここは良い]
#2 [根拠が要る] 「OIDC に統一」 なぜ OIDC かを足して
#2 言い切りすぎ
## 指摘した段落
#1 認証方式
#2 認証は OIDC に統一します。
## 書き換え
#1 の後に追加 (参考にして直す)
後: 新しい段落
#2 移動 (#3 の後へ)
前: 認証は OIDC に統一します。
#3 書き換え (そのまま)
前: 既存ユーザーは初回ログイン時に移行します。
後: 既存ユーザーは初回ログインで移行します。
全体へのコメント: 全体に短く
---
上の指摘と書き換えを反映して文書を直してください。書き換えと追加は、(そのまま) の文は一字一句そのまま使い、(参考にして直す) の文は意図に沿って前後の文に合わせて直してください。「ここは良い」の指摘がある箇所は直さないでください。指摘も書き換えも無ければ、そのまま完了報告に進んでください。
```

- 1 行目は `【doc-desk 回答】` + `documentId` です。2 行目の `対象:` は画面の HTML ファイルで、分けて出したときは末尾に `(<index>/<total>)` が付きます。
- `## 指摘` の各行は `#段落番号 [チップ] 「選んだ文字列」 コメント` です。チップ、選んだ文字列、コメントは、無ければ省かれます。段落番号の順、同じ段落の中は人が付けた順です。指摘が無ければ `(指摘なし)` の 1 行です。
- 行末に `(Claude の候補)` が付いた指摘は、あなた自身が出した候補を人が採用したものです (例: `#2 [根拠が要る] 「OIDC に統一」 なぜ OIDC かを足して (Claude の候補)`)。人の指摘と同じく反映します。人が却下した候補は届きません。全体へのコメントの候補を採用したときは、全体へのコメントに `[チップ] コメント (Claude の候補)` の行として入ります。
- チップは次の 9 種です: 短くする、言い換える、分かりやすく、具体例を足す、根拠が要る、削る、順序を入れ替える、図を直す、ここは良い。
- `## 指摘した段落` は、指摘の付いた段落の文字列です (400 文字を超える分は `…`)。表の行はセルを ` | ` でつないだものです。この文字列を元の文書と照らし合わせて、直す場所を探します。
- `## 書き換え` は、人がその場で直したもの (添削) があるときだけ出ます。次の 4 種で、段落番号の順、同じ段落の中は書き換えか削除、移動、追加の順です。
  - `#2 書き換え (<使い方>)` の後に `前: <書き換える前の全文>` と `後: <書き換えた後の全文>`
  - `#4 削除` の後に `前: <消す段落の全文>`
  - `#5 移動 (#1 の後へ)` の後に `前: <動かす段落の全文>`
  - `#6 の後に追加 (<使い方>)` の後に `後: <足す段落の全文>`
- 書き換えと追加の `<使い方>` は、人が画面で選んだ `そのまま` (既定) か `参考にして直す` です。扱いは 6 章の 1 のとおりです。
- `前:` と `後:` は書式を外した文です。文が複数行なら、2 行目以降は行頭に空白 2 つが付きます (空白 2 つは文の一部ではありません)。表の行の `後:` は、セルを ` | ` で区切った文です。
- 全体へのコメントの扱いは回答固定形 v1 と同じです (`references/reply-format-v1.md`)。人の記述は一字一句そのまま扱います。
- 迷うときだけ `doc-desk/<label>.answer.json` を読みます。形は `{ "kind": "review", "documentId", "revision", "comments": [{ "block", "chip", "quote", "text", "source"?: "claude" }], "edits": [{ "kind": "rewrite" | "delete" | "move" | "add", "block", "text"?, "mode"?: "exact" | "guide", "to"? }], "blocks": { "<段落番号>": "<文字列>" }, "globalNote", "submittedAt" }` です。
- `failed` で人が回答 JSON をチャットに貼ったときは、Claude がこの形に当てはめて読みます。

## 6. 指摘の反映と完了報告

1. 書き換えを先に反映します。段落番号は画面が振った番号で、元の文書の位置は `前:` の文を元の文書と照らし合わせて探します (書式の印は無視して照らし合わせます)。
   - 書き換え (そのまま): 段落の文を `後:` の文に置き換えます。文字は一字一句そのまま使い、言い換えません。元の段落にあった太字やコードの印は、後の文に同じ語が残っていれば付け直し、無くなっていれば外します。
   - 書き換え (参考にして直す): `後:` の文は、人がこう直したいという意図の見本です。その意図 (言いたいこと、長さ、語調) に沿って、前後の文、文書の用語、`references/document-lint.md` に合う文を Claude が書き、段落を置き換えます。見本の語は、合う限りそのまま使います。
   - 削除: 段落を消します。
   - 移動: 段落を、指定された段落の後へ動かします。移動先の段落も書き換えや削除の対象なら、書き換えた後の位置で考えます。
   - 追加: 指定された段落の後に、`後:` の文を段落として足します。`(そのまま)` なら文字は一字一句そのまま使い、`(参考にして直す)` なら書き換えと同じく意図に沿って Claude が書きます。箇条書きの項目の後なら項目として、表の行の後なら行として足します。
2. 指摘を 1 件ずつ、元の文書 (Markdown など) で直します。書き換えた段落への指摘は、書き換えた後の文に当てはめます。`doc-desk/<label>.doc.html` は直しません (何に指摘したかの証跡です)。
3. 「ここは良い」の指摘が付いた箇所は直しません。
4. 直した後、`references/document-lint.md` の 5 章の手順で、指摘で直した箇所を検査します。`(そのまま)` の書き換えと追加の文は、検査で引っかかっても言い換えません。気になる点は完了報告で人に伝えます。`(参考にして直す)` で Claude が書いた文は、検査して直します。
5. 指摘の反映で文書が大きく変わり、人に見直してほしいときだけ、`revision` を進め、`label` を変えて指摘の画面を出し直します。
6. 完了報告には、書き換えと指摘を 1 件ずつ並べ、それぞれに反映した箇所か、直さなかった理由を添えます。`(参考にして直す)` の書き換えと追加は、人が書いた文と Claude が書いた文を並べて示します。指摘の画面の HTML (`doc-desk/<label>.doc.html`) と回答 (`doc-desk/<label>.md`) も絶対パスで示します。
