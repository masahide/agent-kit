# 出題前の試問 (preflight) — open_form を呼ぶ前に、文脈ゼロの読者で試す

質問票を書いた Claude は題材の全文脈を頭に持っています。だから「これで伝わる」の自己判定は構造的に甘いです。人に見せる前に、**何も知らない subagent に質問票だけを渡して試問します**。この試問が質問票の日本語検査も兼ねるので、別の検査を重ねません (`references/question-lint.md` の自己検査は試問の前に済ませておきます)。

akapen の試問 5 問を土台にしています。フォームには絵 (対立軸の図) が無いので、絵の検査を「利点と代償の文だけで選択肢を弁別できるか」に置き換えています。

## 試問 5 問

検査員に渡すのは **質問票の Markdown と読者宣言 1 行だけ**です。作業の経緯、元のコード、会話の文脈は渡しません。

1. **選択肢の弁別** — 各問について、それぞれの選択肢を選んだ場合に文書 (設計・仕様・企画) がどう変わるかを、選択肢の `label` と利点・代償の文だけから説明せよ。説明できない問い、利点と代償が互いの裏返しで区別がつかない問いを挙げよ。
2. **引用の有無** — 各問に実測の引用 (`file:line` か実行結果) が載っているか。載っていない問い、引用が問いの判断材料になっていない問いを挙げよ。
3. **実質 1 択の検出** — 推奨でない選択肢を選ぶ理由が読み取れるか。読み取れない問いを挙げよ (その問いは人に判断を求めていない)。
4. **音読と要約** — 音読して不自然な文、意味の取れない文を逐語で挙げよ。続けて、30 秒で趣旨を 3 文で言え。
5. **内輪語の列挙** — 読者宣言の許可語の外で、説明なしに使われている語や初見の造語を列挙せよ (用語欄で定義済みの語は除く)。

## 質問票の Markdown

質問票 JSON を次の形に落として、プロンプトに直接貼ります (5 問以内なので長くなりません)。ファイルに書く必要はありません。

```markdown
# <title>

<conclusion>

## 用語
- <term>: <definition>

## <テーマの name>

### 問 <通し番号>. <問いの title>
根拠: <cite>
- <選択肢 id>. <label> (推奨) — 利点: <pros> / 代償: <cons>
- <選択肢 id>. <label> — 利点: <pros> / 代償: <cons>
補足欄: <note.placeholder か「補足があれば 1 行で」>

## 表: <表の title>
| <列名> | <列名> | <列名> |
|---|---|---|
| <セル> | (入力) | (入力) |

## <globalNote.label か「全体へのコメント」>
(自由記述)

未選択の問いはお任せ (推奨案) で進みます。
```

通し番号はテーマ順 → 問い順で 1 から振ります (回答固定形の `Qn.` と同じ番号です)。表の `editable` が `true` のセルは `(入力)` と書きます。`glossary` が無ければ「用語」の節を省きます。

## Agent ツールでの呼び方

`Agent` ツールで新しい subagent を立てます。`subagent_type` は `general-purpose` です (`fork` は会話の文脈を引き継ぐので使いません)。**結果を受け取るまで `open_form` を呼ばず、応答も終えません。** subagent の完了通知が届く前に次へ進むと、検査の結果を読まずに人へ質問票を出すことになります。

prompt の雛形:

```
次の Markdown は、文書を書く前に人に判断を求める「質問票」です。あなたは何も知らない読者として読み、5 つの検査に答えてください。
読者宣言: <誰が読むか> + 説明なしで使ってよい語は <語1, 語2, …> だけ

--- 質問票ここから ---
<質問票の Markdown>
--- 質問票ここまで ---

1. 各問について、それぞれの選択肢を選んだ場合に文書 (設計・仕様・企画) がどう変わるかを、選択肢の名前と「利点 / 代償」の文だけから説明してください。説明できない問いは「説明不能」と書いてください。利点と代償が互いの裏返しになっていて、選択肢の違いが区別できない問いがあれば挙げてください。
2. 各問に実測の引用 (file:line か実行結果) が「根拠:」として載っていますか。載っていない問い、引用が問いの判断材料になっていない問いを挙げてください。
3. 推奨でない選択肢を選ぶ理由が読み取れますか。読み取れない問いを挙げてください。
4. 音読して不自然な文、意味の取れない文を逐語で挙げてください。次に、この質問票の趣旨を 30 秒で 3 文で言ってください。
5. 読者宣言の許可語の外で、説明なしに使われている語や初見の造語を列挙してください (「用語」の節で定義済みの語は除く)。

出力は検査ごとに「通過 / 落ちた問いと理由」で。質問票を直す提案は不要です。
```

読者宣言の例: `このリポジトリを保守する開発者。説明なしで使ってよい語は HTTP / JSON / ログイン / セッション`。読者宣言は質問票の `glossary` を決めたときの読者と同じにします。

## 判定と打ち切り

| 結果 | 扱い |
|---|---|
| 1〜3 で落ちた問いがある | 言い換える / 問いを落とす / 選択肢を書き直す (下の節)。直してから再試問 |
| 4 で不自然な文が挙がった | その文をほどく (一文一義に分ける、主語を補う)。3 文で趣旨が言えなかったら `title` と `conclusion` を書き直す |
| 5 の列挙が 3 語以上 | 一般語に言い換えてから出題する。1〜2 語なら `glossary` で定義する |

再試問は **同じ検査員に差分だけを送って 1 回**です。`SendMessage` で同じ subagent に「直した箇所は問 1 の選択肢 B の利点と、用語欄の追加。検査 1〜3 (と 5) を再判定して」のように送ります。計 2 巡で打ち切ります。

2 巡目の結果の読み方:

- 残ったのが軽微 (語彙 1〜2 語、語順、体言止め) なら、そのまま `open_form` を呼んでよいです。
- 残ったのが重大 (意味の取れない文、選択肢の弁別不能、事実の矛盾) なら、3 巡目に進みません。読者宣言に戻って質問票を書き直し、試問を最初からやり直します。検査で磨ける限界を超えているのは、書き手の側の問題だからです。

質問票が 2 問で短いときは 1 巡で打ち切ってよいです。

## 落ちた問いの直し方

- **弁別できない (検査 1)** — 選択肢の `label` を「何をどうする」の文にし、`pros` と `cons` に、その案を選んだときに文書のどの節がどう変わるかを書きます。利点と代償が裏返しなら (A の利点 = B の代償)、片方に別の観点 (費用、期間、影響範囲、可逆性) を足します。それでも違いが書けないなら、2 案は同じ案です。1 つにまとめて問いを落とします。
- **引用が無い (検査 2)** — 引用が無い問いは「まだ調べ足りない問い」です。自分で `file:line` か実行結果を調べ、事実で答えが決まるなら問いごと消します。人に残すのは決定 (好み、優先度、トレードオフの裁定) だけです。
- **実質 1 択 (検査 3)** — 非推奨の選択肢に「選ぶ理由」が無かったら、`pros` に利点を 1 行書き加えます。それでも書けないなら実質 1 択なので、問いを落として推奨案で進め、文書の決定事項に「聞かずに推奨案で確定した」と書きます。
- **不自然な文 (検査 4)** — `references/question-lint.md` の B2, B4, C1, C2 で直します。
- **内輪語 (検査 5)** — 注釈を加えるのではなく、一般語に置き換えます。どうしても要る語だけ `glossary` に 1 行で定義します。Claude が作った ID や記号名は問いの文から消します。
